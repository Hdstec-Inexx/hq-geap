# Áudio ingerido pelo n8n no bucket de objetos; API só armazena a referência

O áudio do Atendimento é persistido no bucket de objetos (`hq-geap`, MinIO) pelo pipeline de ingestão no n8n — que baixa o áudio da ElevenLabs pelo `conversation_id` e sobe o objeto —, nunca pela API. A chave do objeto é `{conversation_id}.mp3` (flat, sem prefixo de pasta — convenção já em produção no n8n; a extensão garante o Content-Type `audio/mpeg` no objeto, do qual o player do navegador depende) e chega à API pronta, como `audio_reference`, no payload de ingestão (mesma fronteira do ADR-0007). A API apenas grava a referência em `audio_url` e resolve URLs assinadas de leitura (15 min) na consulta do detalhe. Alternativa rejeitada: a API baixar o áudio sob demanda da ElevenLabs — quebraria a fronteira de que só o n8n fala com a ElevenLabs e deixaria a disponibilidade do áudio dependente da retenção dela.
